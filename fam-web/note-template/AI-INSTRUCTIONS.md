# Инструкция для ИИ: конспект FAM

Ты готовишь математический конспект по материалу пользователя. Используй приложенный HTML-шаблон FAM. Сохрани его оформление, интерактивное оглавление, управление доказательствами и экспорт PDF. Заполни содержанием по источнику. Не превращай текст в рекламную страницу и не добавляй слоганы.

## 1. Источник и математическая точность

- Сохрани определения, условия теорем и используемые обозначения. Проверяй поле, размерность, область определения, кванторы и исключительные случаи.
- Не выдумывай преподавателя, номер лекции, дату, ссылки на источники или утверждения, которых нет в источнике. Неясные места обозначай явно. Дополнительные пояснения отделяй от материала лекции.
- Не выдавай иллюстрацию или несколько числовых примеров за доказательство общего утверждения.
- Для каждого доказательства напиши две самостоятельные версии: краткую идею и полный строгий текст. Идея объясняет решающий ход; полное доказательство можно читать без идеи, оно не пропускает необходимый переход словами «очевидно».
- Не добавляй блок доказательства там, где нет утверждения, требующего доказательства. Если доказательство в источнике отсутствует и ты его не восстановил, честно укажи это вместо пустого спойлера.

## 2. Работа с шаблоном

Предпочтительный исходник — `source.html`. CSS и JS находятся отдельно для разработки; после сборки читателю передаётся **один автономный HTML**. Если предоставлен только собранный HTML, редактируй в нём текст лекции и метаданные, сохраняя встроенные шрифты, KaTeX, CSS, JavaScript и лицензии побайтно.

1. Измени `title`, description, предмет, заголовок и подзаголовок. Удали пометку «Пример оформления» в реальной лекции. Не переноси демонстрационный текст про линейные отображения в другую тему.
2. Работай между `FAM:CONTENT-START` и `FAM:CONTENT-END`. Сохрани панель `FAM:CONTROLS`, `noscript` и `#math-error` ровно в одном экземпляре. Оболочку, диалог PDF и технические маркеры не меняй.
3. Разделы оформляй как `section.chapter` с `aria-labelledby`, ведущим к уникальному `h2`. У заголовка раздела должен быть `id` и `data-toc` с коротким текстовым названием. Для подраздела, который нужен в оглавлении, используй `h3` с `id` и `data-toc`. Оглавление заполняется автоматически; его список вручную не правь.
4. Все ID уникальны и стабильны. Используй латинские буквы, цифры и дефисы. Внутренние ссылки имеют вид `href="#id"`. Ссылка на скрытое доказательство должна вести на ID его полного блока: переход автоматически раскроет его. Для ссылки на идею укажи ID блока идеи.
5. Сохраняй структуру существующего `.proof[data-proof]`: уникальный ID контейнера; `.proof-controls` с тремя кнопками `data-proof-mode="idea"`, `"full"`, `"hidden"`; отдельные блоки `[data-proof-idea]` и `[data-proof-full]`, каждый с собственным ID. Дай группе кнопок содержательный `aria-label` с номером теоремы. Не вложи одно доказательство в другое. Состояниями, ARIA и скрытием управляет готовый JS.
6. `statement definition` — определение; `statement theorem` — утверждение; `statement theorem featured` — центральная теорема; `worked-example` — разобранный пример; `note` — содержательное замечание. Используй существующую типографику без отдельных «дизайнов» на каждую теорему. Нумерация содержательных блоков задаётся автором и должна совпадать со ссылками.
7. Формулы: `$…$` внутри строки и `\[…\]` для выключных. При необходимости оборачивай выключную формулу в `.equation`. В обычном HTML экранируй `<` как `&lt;`, `>` как `&gt;`, `&` как `&amp;`. Для длинных формул используй осмысленные переносы через `aligned` или `gathered`, а не уменьшение до нечитаемого размера. Используй только поддерживаемый KaTeX синтаксис; произвольный HTML в TeX запрещён.
8. У таблиц должны быть `caption`, `thead`, заголовки `th` со `scope` и обёртка `.table-scroll`. Не помещай всю лекцию в таблицу.
9. Изображения в итоговом HTML встроены как `data:image/svg+xml;base64,…` или `data:image/png;base64,…`. У каждого изображения содержательный `alt`; у `figure` — `figcaption` с номером, обозначениями и необходимыми оговорками. Рисунок должен работать офлайн, без соседних файлов или CDN. SVG не содержит скриптов, внешних ссылок, `foreignObject` и внешних шрифтов. Текстовые метки экспортируй в контуры, если переносимость шрифта иначе не обеспечена.

## 3. Единственный движок иллюстраций — Asymptote

**Используй Asymptote: https://asymptote.sourceforge.io/**

Не используй библиотеку заранее заготовленных рисунков. Для каждой задачи напиши самостоятельную программу Asymptote из её математического содержания. Набор типов рисунков не ограничен примерами ниже. Если задача новая, изучи официальную документацию движка и разработай построение; не подставляй приблизительно похожую картинку.

Asymptote строит графику по коду, но не доказывает, что исходная модель правильна. Успешная компиляция не является математической проверкой. Обязательно выполни обе проверки из следующего раздела.

### Подготовка

- Перед работой проверь доступность `asy --version`, версии и зависимости выбранного формата. При отсутствии Asymptote явно сообщи об этом и организуй установку официального движка в разрешённой среде. Не выдавай непроверенный код или пустое место за готовую иллюстрацию.
- Используй официальную документацию: https://asymptote.sourceforge.io/doc/ и модуль 3D https://asymptote.sourceforge.io/doc/three.html . Учитывай зависимости от TeX и выбранного графического backend. Не утверждай, что SVG/PDF экспорт доступен, пока его не проверил в текущей среде.
- Предпочитай статический SVG для плоских схем. Для сложной 3D-сцены используй корректный рендер со скрытием поверхностей и статический PNG достаточного разрешения либо проверенный статический векторный экспорт. Не включай WebGL, интерактивный PDF или вращение сцены в конспект.
- Для плоской векторной проекции 3D с `render=0` не полагайся на полноценное скрытие поверхностей: у этого режима есть ограничения. Выбери другой способ рендера, если результат вводит в заблуждение.

### Построение произвольного рисунка

- Сначала зафиксируй математические объекты, определения, связи и то, что должен объяснять рисунок. Затем вычисли необходимые координаты и выбери представление. Все зависимые точки и связи вычисляются из исходных данных, а не выставляются «на глаз».
- В аналитической геометрии задавай настоящие 3D-координаты, уравнения и нормали; лишь затем выбирай камеру и проекцию. Проверяй пересечения, ортогональность, видимость, принадлежность точек. Не рисуй прямой угол только потому, что две проекции выглядят перпендикулярными. Масштабы осей согласованы или явно подписаны. Если один ракурс скрывает смысл, добавь второй статический вид.
- В алгебре проверяй действие отображения на выбранных объектах, соглашение о векторах-столбцах/строках, порядок композиции, размерности и используемое поле. Не изображай произвольное абстрактное пространство как геометрически точную плоскость без оговорки. Для коммутативной диаграммы проверь равенство композиций по нужным путям.
- В дискретной математике строить рисунок нужно по точному множеству вершин, рёбер и отношений. Проверяй направления, петли, кратные рёбра, степени, веса, порядок композиции перестановок. Пересечение рёбер не означает вершину без явной точки. В диаграмме Хассе изображай покрытия, а не все сравнимые пары, и соблюдай направление порядка.
- В других темах самостоятельно сформулируй соответствующие инварианты. Эта инструкция не является перечнем допустимых сюжетов.
- Визуальный язык: светлый фон; тёмные основные линии; приглушённые зелёный, синий и охра для различения ролей; одинаковые роли имеют одинаковый цвет. Цвет дублируется обозначением, типом линии или подписью. Согласуй толщины линий, размеры стрелок и подписей между всеми рисунками одной лекции.
- Не используй декоративные свечения и перспективные искажения, мешающие чтению. Обеспечь поля для подписей. На печати A4 подписи должны читаться без увеличения, ориентир — не менее 9 pt при фактическом размере рисунка.

## 4. Обязательная повторная проверка ИИ

После построения остановись и проведи отдельный проход проверки. Не ограничивайся перечитыванием собственного кода. Если доступен отдельный проверяющий ИИ, передай ему условие, рисунок и обозначения; иначе выполни самостоятельный критический проход. Не заявляй о независимой проверке другим ИИ, если его не было.

**Математическая проверка:** заново сопоставь рисунок с исходным условием. Проверь необходимые равенства, неравенства и инварианты вычислением; при рациональных данных предпочитай точные вычисления, при приближённых укажи точность и допуск. Проверь граничные и вырожденные случаи, значимые для данного утверждения. Убедись, что обозначения в рисунке, формуле, подписи и доказательстве совпадают.

**Визуальная проверка:** скомпилируй Asymptote, открой полученное изображение и осмотри именно результат. Затем проверь его внутри HTML и в PDF при реальном размере. Ищи пересекающиеся подписи, обрезанные стрелки, ложные пересечения, исчезнувшие задние рёбра, слабый контраст, неверную глубину и непропорциональные оси. Исправь и повторно отрендери найденные ошибки.

В отдельном отчёте укажи для каждого рисунка: что он иллюстрирует, какие свойства были проверены и как, результат компиляции, результат просмотра, исправления и оставшиеся ограничения. Привяжи отчёт к финальным файлам по SHA-256. Не добавляй в читательский интерфейс плашки «проверено ИИ» и не обещай абсолютное отсутствие ошибок.

Если не можешь выполнить компиляцию, вычисления или просмотр, сообщи, какой этап остался непроверенным. Не помечай его как выполненный. Передай отдельный исходник `.asy` и обозначь незавершённость; не подменяй результат выдуманным изображением.

## 5. Приёмка конспекта

Перед выдачей открой итоговый HTML и проверь:

- Начальное состояние: идеи видны, полные доказательства скрыты. Глобальные три режима работают для всех блоков; индивидуальные переключатели не меняют соседние доказательства.
- Полное доказательство можно открыть сразу. Ссылки на скрытое доказательство раскрывают его и ведут к нужному месту.
- Оглавление содержит все необходимые разделы, подсвечивает текущий и работает при узком экране. На странице нет общей горизонтальной прокрутки; длинная формула прокручивается только внутри своего блока.
- Формулы не показывают сырой TeX и не имеют сообщений об ошибках. Рисунки встроены, загрузились и совпадают с проверенными файлами.
- Экспорт PDF имеет три режима, по умолчанию полный. Выбор варианта PDF не меняет состояние блоков на экране. Обычный Ctrl+P печатает полный конспект.
- В PDF нет интерфейса, обрезанных формул и рисунков, пустых страниц от вёрстки. Проверь начало, середину и конец длинного доказательства; не запрети разрыв целого длинного доказательства между страницами.
- HTML открывается офлайн; браузер не запрашивает внешние шрифты, библиотеки и картинки.

Передай итоговый автономный HTML, исходный текст/исходники Asymptote для дальнейших правок и отдельный честный отчёт проверки. PDF прилагай, если экспорт действительно выполнен. Не публикуй на GitHub и не изменяй оригиналы материалов без отдельного запроса.

## 6. Темы и иллюстрации

Шаблон имеет системную, светлую, тёмную и пергаментную темы. Сохрани переключатель `#note-theme`. Тема хранится только как настройка оформления; внутри изолированного просмотрщика она может сохраняться лишь на время просмотра. PDF всегда использует светлую палитру.

Для каждой иллюстрации Asymptote подготовь три статических экспорта одной и той же математической сцены. Меняй только палитру и фон. Координаты, камера, масштаб, текст, объекты, рёбра и смысл цветов должны оставаться одинаковыми. Не генерируй три независимых построения. Используй один исходник сцены с параметром палитры. Это требование к произвольным новым рисункам, а не библиотека заготовок.

В HTML используй `figure.themed-figure` с тремя дочерними `img`: атрибуты `data-figure-theme="light"`, `data-figure-theme="dark"`, `data-figure-theme="parchment"`. Все три `src` — встроенные data URI. У всех версий одинаковое содержательное `alt`, одинаковые пропорции и размеры холста; одна общая подпись `figcaption`. CSS сам выбирает нужную версию, при печати всегда показывает только light. Нельзя опускать одну из трёх версий: это оставит рисунок пустым в соответствующей теме.

Палитры: light — фон #f8f6f0, текст #202e29, акцент #8a6b32; dark — фон #17221e, текст #e8e9dd, акцент #d5b878; parchment — фон #eee3cc, текст #372f22, акцент #795a24. Дополнительные цвета подбирай по контрасту к конкретному фону. Цвет обозначает одну и ту же математическую роль во всех темах. Дублируй цвет подписью или стилем линии. Полупрозрачные поверхности проверь на каждом фоне. Не применяй CSS invert/hue-rotate: это может исказить смысл цветов и ухудшить различимость линий.

Если дано готовое изображение, которое нельзя корректно перекрасить (например, скан источника), оставь один `img` внутри `figure.figure-plate`: он будет на собственной светлой подложке во всех темах. Не представляй это как адаптивную перекраску. Для новых иллюстраций предпочтительны три экспорта Asymptote.

При повторной проверке ИИ открой все три версии, сравни их геометрическую идентичность и обозначения, читаемость подписей, видимость пунктирных и задних рёбер. Проверь переключение тем в HTML и светлый рисунок в PDF, созданном из тёмной темы. В отчёте укажи результаты для каждой палитры, не заявляй проверку неоткрытых изображений.
